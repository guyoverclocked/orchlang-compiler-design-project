# Response to the independent simulated SCP audit

This is an implementation response to the user's audit, not a journal rebuttal
to an official decision. The report's 7.8/10 is a subjective readiness judgment,
not an acceptance probability. Its suggestions were assessed against the code
and evidence rather than treated as instructions that override the user.

## What is actually stopping publication readiness?

The audit accepts the central theorem as a correctly conditional result and
independently corroborates the retained logical-trace/output records. Its strongest
scientific objection is the gap between an abstract always-conforming world and
a partial physical host whose refusals can be observed. The other major risk is
significance under an app-controlled logical observer: if logs may be freely
normalized, expensive cover work may be unnecessary. Novelty is an integration
and assurance contribution, with bounded application validity and uneven utility.
The editorial fit is therefore an **SCP Research Paper**, not an assumed OSP.

Some requested experiments are strengthening options, not documented universal
journal requirements. We adopted the report's offered offline-assurance framing
instead of claiming that local instrumentation supplies a provider-authoritative
gateway. No extra test count is presented as buying a higher reviewer score.

## M1: restricted conformance and observable refusal

Implemented `proof/AdmissionDomain.lean` and compiled it with Lean 4.19.0.
`World.ConformsOn` only constrains supported reached request contracts.
`RunsIn` follows evaluated stores and includes model cover work. The new proofs
establish exact shaped traces on that domain, equal completion/refusal under
uniform admission, and completion for every advertised input/tape when a
`DomainCertificate` is supplied. The proof contains no `sorryAx`.

The observation type explicitly contains refusal, completion, failure and unknown
dispatch. The ideal adapter is a noncomputable specification. The paper states
that it does **not** prove the Python failure protocol refines this specification,
automatically synthesize the all-inputs invariant, or cover every public-branching
program accepted by the older checker. These remain genuine limitations.

The executable challenge gives one completed short-secret run and one pre-dispatch
refusal for a longer secret. A separately stated finite character-world domain
checks all 15 binary strings of length at most three across three seeds, with
45 successful equal-shape runs. A new test also keeps unknown dispatch observable
and retains its unconfirmed reservation. This directly falsifies the unsafe
inference that fail-closed resource checks imply failure noninterference.

## M3 and M4: transparency falsification and current-code evidence

A protocol is written before inference and binds code/model bytes and every
selected input. It specifies 48 paired workflow checks across switch, email and
corrective RAG, Llama/Qwen, greedy/sampled decoding, seeds 0/17 and whitespace
boundaries. Shortest/longest examples and an alternate historical decision are
chosen deterministically; a missing alternate class is not invented.

A separate 192-pair transparency matrix crosses two model families, two stop
profiles, two temperatures, two seeds, three prompt classes, two visible caps
and two forced-output gaps. Padding slack spans 0/16/64 tokens. All attempts,
including failures or mismatches, remain in raw JSONL. These are finite targeted
checks, not general transparency guarantees or useful-task accuracy estimates.

The completed matrix has **192/192 equal visible outputs and 192/192 exact
logical counts**, with no failed attempt. Independent JSON reconciliation checks
all 102 planned application/baseline executions and all 192 primitive pairs,
reconciling **646 local model calls** without an audit error. In 224 natural calls,
the low-level generator yields a stop ID excluded by the declared logical-output
convention. The deliberately corrupted input count is detected.

All 48 workflow pairs completed with equal saved fields, equal recorded store
slots and expected shaped traces. Among 18 unmodified greedy examples compared
with historical saved fields, **six differ**, all in Llama switch/email. This is
reported rather than hidden. Profiles and versions differ, and historical records
lack request/ID evidence, so the observation is not attributed to one change.
It confirms why current-code pairing and historical version separation matter.

The JSON-only reconciler checks the exact expected experiment keys, including
duplicates and missing/foreign cases, and includes a count-corruption negative
control. The generated revision summary is authoritative for actual outcomes;
no historical record is relabelled as a fresh execution. The 1,172 main and 512
replication denominators remain unchanged; neither the old 21 conformance pairs
nor the new revision checks are silently pooled into them.

Real-backend unshaped, aligned, all-branches, uniform and random-padding switch
executions use the same backend/observation alphabet in a bounded comparison.
Reporting normalization is explicitly a projection of an existing execution,
valid only when the observer contract permits it. The two greedy baseline
examples do not establish comparative confidentiality for arbitrary inputs.

A separate authored two-route microbenchmark exercises actual model cover work.
Its 20 executions (24 model calls) retain both secret routes under both model
families and all five executed conditions. All useful saved outputs agree.
Unshaped/randomly padded runs have two distinct observed traces; aligned,
all-branches and uniform-cell runs have one. Alignment uses one model call
where all-branches shaping uses two. Mean weighted logical usage is 147 vs 246
for Llama and 140 vs 232 for Qwen. These two-secret examples are not a statistical
distribution guarantee, an untouched external application or a measured bill.

## What remains

cannot guarantee acceptance or establish deployment security. The remaining
external actions are author review/declarations, independent human replay,
