# Second-round revision work

The full second-round review was read. Its recommendation and numeric score are
informal assessments, not an editorial decision or a guarantee of acceptance.

The revision targets three substantive evidence gaps:

1. Execute all 1,684 planned original/shaped pairs on one immutable corrected
   implementation, with pinned native libraries and streaming local API evidence.
2. Connect the Lean admission checker to real serialized workflow candidates and
   an explicit executable byte-bounded value interface. Both original and shaped
   programs must use that same interface. Preserve the native-code trust boundary.
3. Test a single-batch, sequence-isolated prefill prototype and a separately
   contracted categorical CRAG grader. Neither batch length alone nor grammar
   compliance proves a stronger observation model or semantic accuracy.

Initial vocabulary inspection found maximum native token-piece sizes of 128
bytes in all three pinned GGUFs. It also exposed a fixed 32-byte detokenization
buffer in the installed Python wrapper. A resizing decoder and regressions are
therefore included before the homogeneous execution freeze. The review's
suggestion that all pieces fit in 32 bytes is not adopted.

The four alleged PDF typos will be checked against source and rendered glyphs.
They will not be changed merely to match an OCR transcription. The existing
source already uses llama1b, angle-bracket notation, generated citation brackets
and + OK labels.

Existing full-corpus evidence remains immutable. New measured results will enter
the paper only after completeness, accounting, source and paired-output checks.
The final clarity pass will again use academic-humanizer and preserve the revised
numbers, equation content and citations.
