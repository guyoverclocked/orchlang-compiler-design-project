# Submission preparation

The selected target is **Science of Computer Programming**. The current manuscript
is `paper/main.tex`; its reviewed PDF is `output/pdf/orchlang-scp-author-review.pdf`.
Use `publication/README.md` for reproduction and archive verification.

The scientific contribution is a bounded workflow implementation connecting
source-bound shaping validation, explicit model contracts, logical usage and
auditable execution. Lean proves conditional core properties. The parser,
frontend and backend remain trusted; the paper does not claim timing protection,
provider invoice equivalence, useful task accuracy in every port, or verified
end-to-end compilation.

Read these documents before selecting submission files:

- `publication/NOVELTY_AND_JOURNAL_ASSESSMENT.md`: primary prior-art comparisons,
  separating examples, SCP fit and material reviewer risks.
- `publication/CLAIM_LEDGER.md`: each claim's evidence and limits.
- `publication/AUTHOR_REVIEW.md`: actual author approvals and declarations still
  needed; blank fields are not consent.
- `publication/POST_FREEZE_CHANGES.md`: distinct experiment and release versions.
- `publication/COVER_LETTER_DRAFT.md` and `publication/highlights.txt`: review drafts.

Run `python publication/build_evidence.py --require-complete` and verify the
archive manifest. Check the current SCP Guide for Authors directly before
submission; its detailed web page was inaccessible during this audit. The scope
match is plausible, but journal acceptance and independent reproduction cannot
be established by local tests. Public archival deposition and actual submission
require the authors' approved version and accurate human declarations.
