## Verified fit details

- **SCP:** the publisher describes a broad software-design/programming-methods
  scope, including language implementation/evaluation, formal techniques,
  software tools, and experimental software technology. It has separate
  Research Papers and Software tracks; the Software Track publishes OSPs for
  useful programming/language and software-development software. The EAPLS
  call dated 27 August 2025 says an OSP includes a tool and short description
  (typically around six pages in regular SCP format), with source/link and
  documentary material such as user manuals. It lists six review dimensions:
  originality/novelty/significance, source quality, documentation,
  reproducibility, accessibility, and manuscript clarity. The call does not
  present its typical length as a hard limit; it also asks for an innovative
  contribution and a recognized software license, which the repository's MIT
  license addresses. The current guide was subsequently read in full through
  the browser on 9 October 2026. Its suggested 3–6-page budget covers abstract
  and running text and excludes supporting matter. It requires the official
  OSP template, public software, a C1–C9 metadata table, a source ZIP for LaTeX,
  and separate highlights. The earlier HTTP 403 limitation is superseded by
  this direct check. [Verified requirements](SCP_AUTHOR_REQUIREMENTS.md),
  [EAPLS SCP Software Track call](https://eapls.org/news/issues/open-call-for-software-submissions-science-of-computer-programming-software-track-xjw27/),
  [SCP scope and tracks](https://shop.elsevier.com/journals/science-of-computer-programming/0167-6423),
  [linked author guide](https://www.sciencedirect.com/journal/science-of-computer-programming/publish/guide-for-authors)
- **JSS:** the current page includes software engineering for AI systems and
  says regular articles should support claims with evidence, such as empirical
  studies, simulations, formal proofs, or other validation. It describes both
  short single-contribution and longer survey/solution NITPs and says full
  validation is not required for NITPs, although preliminary results are
  welcomed. [JSS scope and NITP description](https://shop.elsevier.com/journals/journal-of-systems-and-software/0164-1212)
- **STTT:** the journal scope is tool development and use for software
  development and verification. It is hybrid: subscription publication has no
  APC; the current OA APC is £2,490 / US$3,390 / €2,790 before applicable tax,
  with the accepted-date price controlling. [Scope](https://link.springer.com/journal/10009/aims-and-scope),
  [publishing options and fees](https://link.springer.com/journal/10009/how-to-publish-with-us)
- **SoSyM:** its scope concerns theory and practice for software/system
  modeling, language engineering, and model-based engineering. It is hybrid:
  subscription has no APC; current OA APC is £2,290 / US$3,190 / €2,590 before
  tax. [Scope](https://link.springer.com/journal/10270/aims-and-scope),
  [publishing options and fees](https://link.springer.com/journal/10270/how-to-publish-with-us)
- **SoftwareX:** Elsevier describes it as a peer-reviewed, open-access journal
  for detailed articles about research software and its application, with a
  stated reproducibility/discoverability aim. [Publisher description](https://www.elsevier.com/en-gb/researcher/author/tools-and-resources/research-elements-journals)
- **Software Impacts:** Elsevier describes it as a multidisciplinary,
  peer-reviewed, open-access journal for short articles about software that
  addresses a research challenge; its description emphasizes application,
  reuse, and a scholarly reference. The official page directs authors to the
  Original Software Publication section of the Guide for Authors. The linked
  template retrieved in this audit is version 2 (July 2021), says public code
  sharing is mandatory, and says the journal only considers submissions using
  that template; check the live guide before relying on those detailed rules.
  [Official journal description](https://www.elsevier.com/en-gb/researcher/author/tools-and-resources/research-elements-journals),
  [publisher-linked OSP template](https://legacyfileshare.elsevier.com/promis_misc/SIMPAC_Article_Template.pdf)
- **JOSS:** requires an OSI-approved software license, obvious research use,
  feature-complete and maintainable software, and evidence of research impact
  and good open-source practices. Privately developed projects need more than
  six months of active public history with evidence of open development; merely
  waiting six months is not sufficient. It has no submission or publication
  fees. Generative-AI use must be disclosed with the tools/models, scope of use,
  and human review confirmation. [Requirements and AI policy](https://joss.theoj.org/about),
  [submission and fee policy](https://joss.readthedocs.io/en/latest/submitting.html)

## Readiness judgment

The present strongest story is an **Original Software Publication** centered
on the compiler, graph/stochastic tools and independent replay pipeline.
The EAPLS criteria make usefulness and software quality central alongside
novelty. The candidate has isolated-install smoke checks for all six graph,
channel and stochastic commands, restricted source adapters, actual offline
LangGraph execution, and a completed 44-stage reproduction. External reuse
has not been established. The exact public candidate identity is supplied
in the release records once frozen. JSS NITP remains a research-paper alternative if the
manuscript presents one contribution with mock-only and purposive evidence.
The theorem must remain at its abstract request/cost model. STTT or SoSyM would
need a complete formal argument and stronger independent or realistic
evaluation.

The checkout has a root MIT `LICENSE` and `CITATION.cff`; repository-owner
authority was checked. Final author review remains necessary. Retain notices for upstream code
or substantial text; the source catalog records the pinned source revisions
and their own licenses, which do not automatically license OrchLang.

The catalog has 17 candidate source files across four repositories; it is not
an execution set. The evaluation executes 15 authored partial projections from
three DSL frameworks, each with base, balanced, and one-extra-call unbalanced
variants. They omit or abstract source semantics as described in the manifest.
This supports bounded expressibility, not 17 ports, independent application
studies, prevalence, or provider billing claims. The overall importance is
moderate in the specified usage-observer threat model, while present deployment
relevance is limited because there is no provider adapter or usage-receipt
study. These are readiness judgments, not acceptance odds.

A separate bounded bridge attempt considered five existing accepted examples
and fifteen existing balanced OrchLang projections without rewriting prompts
or outputs. These 20 repository files are distinct from the 17-row upstream
source catalog above. The compiler accepted all 20; the bridge exported 17
and explicitly excluded three retry examples. Its finite differential grid
recorded 720 source/graph run pairs, 360 secret-trace comparisons, and 1,584
call events with no difference. These are distinct from the 15-pattern source study above:
they test a project-authored source-to-graph adapter under a deterministic mock
oracle, not independent framework ports or a verified translation. The
machine-readable record is [`source_graphs/evaluation.json`](../bench/results/source_graphs/evaluation.json).
