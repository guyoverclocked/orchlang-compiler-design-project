# Mutation taxonomy and executed variants

Date: 2026-10-09

This M01–M10 table is a **design taxonomy** of controlled OrchLang mutation ideas derived from public source patterns, not a record that all ten named cases were executed. None is an upstream bug report, production incident, or claim about an upstream project's security. The currently executed corpus uses one concrete mutation per each of 15 patterns: append one extra model call in one secret-controlled arm. Those 15 extra-call variants are rejected and show a per-contract usage-observation mismatch in the declared mock grids; their results are recorded separately in [`bench/results/sourced.json`](../bench/results/sourced.json) and [`bench/results/sourced_request_sensitive.json`](../bench/results/sourced_request_sensitive.json). The M01–M10 scenarios below must not be counted as additional executed mutation classes unless a separate fixture and result are added.

## Oracle contract used by these fixtures

The abstract theorem uses a shared oracle `Ω(c, k, Q)`, where `c` is a resolved model contract, `k` is that contract's invocation ordinal, and `Q` is the DSL's exact template bytes plus ordered argument values. Equal keys return the same complete abstract outcome and usage; different requests at the same ordinal may return different outcomes. The executable mock is a projection of this model: it has no provider serializer or response text, and request-sensitive mode keys exact template/literal bytes while representing identifier values through mock token-count/flag fields. The input bound separately assumes full abstract per-call cost `I <= ceil(UTF8_bytes(template)/d) + sum(argument bounds)` in a common target-tokenizer unit, with no uncounted overhead or boundary interaction that exceeds the sum. It is not a provider billing contract. See [`docs/FORMAL_CONTRACT.md`](../docs/FORMAL_CONTRACT.md).

| M06 `secret-dependent-retry-count` | P11, the finite retry example | Make the validity/stop predicate depend on the secret so one arm succeeds on attempt one and the other reaches attempt two. | M07 `different-model-order` | P12, two-agent exchange | Keep the total call multiset fixed but make the secret choose between two orderings of the source model identities, with different model rates and ordinal oracle entries. | Reject or report unproved equality unless the specified observer intentionally forgets order and the resulting aggregate is independently shown equal. | Per-model and ordered traces cannot be reduced to a single raw token count without stating the observation. |
| M08 `secret-to-followup-request` | P01 | Make the first request include secret-derived content and pass its response into the second request. ## Porting and reporting rules

1. Keep the source pattern ID, repository revision, file path, source line range, and SHA-256 in every derived fixture's metadata.
2. Put each authored mutation in a separate fixture or a clearly named fixture variant. Never imply the mutation appears upstream.
3. Keep source workload projections and synthetic security mutations in separate benchmark categories. The first checks whether patterns can be represented; the second probes the property and analysis boundaries.
4. If an adapter changes concurrency into sequential calls, removes a loop, stubs retrieval, or removes an output constraint, label it a bounded projection and identify that semantic change in result tables.
5. Do not call a rejection a demonstrated leak unless the declared oracle/price table exhibits unequal observable traces. “Cannot prove equality under this abstraction” is a soundness result, not proof that a live provider leaks.
