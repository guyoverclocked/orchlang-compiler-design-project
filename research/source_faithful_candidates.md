# Public LangGraph candidates for source-faithful analysis

Checked 2026-10-09. Scope: find an existing publicly licensed Python/LangGraph workflow with a source-documented confidentiality boundary, then compare its actual source with the current `integrations/langgraph/source_frontend` subset. Sources below are primary repository files pinned to the observed public revision. No candidate was modified or executed for this review.

## Finding

No candidate found satisfies all requested conditions at once: a credible secret-bearing LLM workflow, an independently stated confidentiality boundary, and source that the current frontend can translate without replacing or approximating its operations. The closest source-analysis candidate is `codewithkachi/agent-incident-triage` at revision [`c08f710acfeefe233329df613fe8358eaac5f350`](https://github.com/codewithkachi/agent-incident-triage/tree/c08f710acfeefe233329df613fe8358eaac5f350). Its README and implementation explicitly place PII redaction before model input; it is MIT licensed and includes an offline mock model. It is a small published demo rather than evidence from an independently deployed or audited production workflow, so it should be treated as a source-faithful validation candidate, not as a real-world security finding.

The strongest documented production-style credential boundary found is LangChain's Open SWE at [`a5d4fd6b2ef713d38a3aa381a9d1462202ebfae7`](https://github.com/langchain-ai/open-swe/tree/a5d4fd6b2ef713d38a3aa381a9d1462202ebfae7), also MIT licensed. Its documentation distinguishes owner OAuth credentials for private-thread server operations from installation credentials in the sandbox and warns that private-thread visibility does not narrow sandbox access. Its graph is assembled through `create_deep_agent`, middleware, tools, runtime configuration, and effects; it is far outside the current source frontend. It is useful security context, but not a faithful current-frontend benchmark.

## Closest source-analysis candidate: incident triage

**Repository and license.** The source is the public MIT-licensed repository [`codewithkachi/agent-incident-triage`](https://github.com/codewithkachi/agent-incident-triage/tree/c08f710acfeefe233329df613fe8358eaac5f350). The checked-out revision was `c08f710acfeefe233329df613fe8358eaac5f350`; its [`LICENSE`](https://github.com/codewithkachi/agent-incident-triage/blob/c08f710acfeefe233329df613fe8358eaac5f350/LICENSE) is MIT.

**Documented boundary.** Its README describes a LangGraph incident classifier and action drafter and states that email addresses, UK phone numbers, and National Insurance numbers are redacted before text reaches a model. It also documents per-call cost tracking and a human approval interrupt before dispatch ([README, guardrails and workflow](https://github.com/codewithkachi/agent-incident-triage/blob/c08f710acfeefe233329df613fe8358eaac5f350/README.md#guardrails-all-tested)). These are repository-authored design claims, not an external audit or assurance about all PII.

**Source matches.** The graph is an actual `StateGraph` with a `TypedDict` state, classifier and drafting model calls, a deterministic enrichment stage, policy computation, conditional routes, and a pre-dispatch human gate ([`src/triage/graph.py`](https://github.com/codewithkachi/agent-incident-triage/blob/c08f710acfeefe233329df613fe8358eaac5f350/src/triage/graph.py)). In `classify`, the source extracts `incident.text`, applies `redact_pii`, and passes the result to the classification call (`graph.py`, lines 66–81). In `draft`, it constructs a request from the classification summary and priority and performs a second model call (`graph.py`, lines 115–138). The PII substitutions are implemented by three explicit regular expressions (`src/triage/guardrails.py`, lines 16–24); schema-invalid output can induce one repair request containing the error (`guardrails.py`, lines 42–53). The included mock model makes offline source-level experiments possible (`src/triage/llm.py`). A sample incident includes synthetic email and phone strings; it does not contain real credentials or a real person's contact data ([`data/sample_incidents.jsonl`](https://github.com/codewithkachi/agent-incident-triage/blob/c08f710acfeefe233329df613fe8358eaac5f350/data/sample_incidents.jsonl)).

**Potential source-derived check, not a vulnerability claim.** An unmodified pair of incident inputs that differ only in a value matched by one of the source's PII patterns should produce the same sanitized classifier request, provided the rest of the incident and model contract are held fixed. Under the repository's deterministic mock and a shared request oracle, this gives a useful trace-equivalence check through the downstream draft request. It tests the stated preprocessing path and composed calls; it does not establish that the regex set detects all PII, that data is absent from checkpoints, or that arbitrary providers behave like the mock. No such experiment is claimed as performed in this candidate search.

**Why it is not admitted by the current frontend.** The implementation cannot be translated unchanged by `integrations/langgraph/source_frontend`:

- The graph is constructed inside `build_graph`; node functions are nested closures over `tracked`, `tracker`, and `sites`. The frontend accepts module-level straight-line node functions.
- `TriageState` is a `TypedDict(total=False)` of nested dictionaries and lists. The frontend requires one plain `TypedDict` with supported scalar fields; its input contract cannot presently type and label the nested `incident.text` independently.
- Model calls are `call_with_repair(tracked, ...)` and `tracked.complete(...)`, with dynamic wrappers, schema validation, and a conditional repair attempt. The frontend recognizes only its explicit pure `request(...)` call form and has no repair semantics.
- The classifier performs `IncidentReport.model_validate`, `redact_pii`, formatting, exception handling, and cost mutation. Enrichment reads a JSON site registry; prioritisation computes from structured results. These computations are not represented by the frontend's literal / text-register expression set.
- Routes are closure-generated on `state.get("error")`; the graph uses `set_entry_point`, conditional edges without a static route map, a checkpointer, and `interrupt_before`. These constructs are outside the currently supported edge and effect subset.

A valid adapter would need to preserve and bind the actual redaction implementation, repair-attempt schedule and validation branch, request templates and arguments, cost guard, and source route semantics. It must not replace `redact_pii` with a manually declared release, assume summaries are always PII-free, drop the retry, or use a hand-authored graph as if it came from source. A bounded projection could end at the pre-dispatch approval boundary only if that exact source prefix and its error outcomes are represented.

## Stronger credential boundary, weaker source fit: Open SWE

The MIT-licensed Open SWE repository's deployment documentation explicitly states: (i) personal MCP connections and user skills are available only in a private thread started by its immutable owner; (ii) private threads use their owner's GitHub OAuth token for server-side GitHub operations, with no bot fallback; and (iii) sandbox GitHub proxy operations still use an installation token in both public and private threads. It separately warns that private-thread visibility and workspace bindings do not reduce sandbox GitHub access ([`docs/INSTALLATION.md`, trust model and thread credential scope](https://github.com/langchain-ai/open-swe/blob/a5d4fd6b2ef713d38a3aa381a9d1462202ebfae7/docs/INSTALLATION.md#repository-trust-model), [credential scope](https://github.com/langchain-ai/open-swe/blob/a5d4fd6b2ef713d38a3aa381a9d1462202ebfae7/docs/INSTALLATION.md#thread-credential-scope)). The repository contains a genuine, configurable LLM coding/review system (`langgraph.json`, `openswe/server.py`, `openswe/reviewer.py`, `openswe/chat.py`), but graph construction goes through `create_deep_agent` and extensive runtime/tool/middleware behavior rather than static source calls. This is a real codebase with a documented boundary; it is not within the static source translator's supported grammar, and extracting a few nearby functions would not amount to source-faithful graph translation.

## First-party docs near-match: private channel streaming

The MIT-licensed [`langchain-ai/docs`](https://github.com/langchain-ai/docs/tree/be3028f3b446d7cfc63b434faf4e594689129251) contains a compact LangGraph `StateGraph` example with `InputState`, `OverallState`, `PrivateState`, and `OutputState` in [`langgraph-graph-api-multiple-schemas.py`](https://github.com/langchain-ai/docs/blob/be3028f3b446d7cfc63b434faf4e594689129251/src/code-samples/langgraph/langgraph-graph-api-multiple-schemas.py). The adjacent [`stream-private-channel.py`](https://github.com/langchain-ai/docs/blob/be3028f3b446d7cfc63b434faf4e594689129251/src/code-samples/langgraph/langgraph-graph-api-stream-private-channel.py) exhibits a private `bar` field in `stream_events(...).values`. The official Graph API doc states that `input_schema`/`output_schema` constrain graph input and `invoke` output but do not hide private channels from `stream_mode="values"`, which includes all channels by default ([Graph API, “Private channels are not redacted when streaming”](https://github.com/langchain-ai/docs/blob/be3028f3b446d7cfc63b434faf4e594689129251/src/oss/langgraph/graph-api.mdx#private-channels-are-not-redacted-when-streaming)). This is a source-level confidentiality boundary and a useful simple counterexample about stream observation, but its Python sample has no LLM call or secret-bearing input and the stream API is not modeled by the current frontend. It should not be presented as an LLM workflow or translated as a model-call finding.

## Recommendation

For an immediate research extension, use incident triage as a **candidate requiring a new source adapter**, not as an already supported program. It offers the best overlap between PII-bearing input, real source-level preprocessing, model-call traces, cost accounting, offline execution, and explicit LangGraph construction. Before describing a compiler result, implement a source-bound extraction of the actual checked revision and differentially compare actual source traces with the extracted model under fixed synthetic inputs and seeds; report unsupported nodes and failure/retry paths separately. If the project requires a currently supported translation with no new adapter, the honest result is no matching workflow found. Open SWE remains a credible future target once the translator can model its dynamic agent/tool runtime, while the docs sample is appropriate only for a separate stream-disclosure study.
