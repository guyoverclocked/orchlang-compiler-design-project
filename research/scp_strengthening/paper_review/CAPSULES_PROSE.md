# Read-only review: capsule claims, proof boundaries, and related work

Reviewed the saved main article and technical supplement against the capsule report, recorded certificates, and `research/publication_upgrade/literature_verified.md` / `literature_sources.csv`. No workflow source or API was executed. This review does not assess the source-run process; the capsule verifier and artifacts were read as records.

## Findings

1. **Clarify what is retained for LangChain messages (minor but concrete).** The supplement says the capsules “retain real LangChain message types” (Technical Supplement, §Execution and source applicability studies, around line 207). The artifact records canonical `message_to_dict` projections produced from actual runtime message objects; Python object identity is explicitly excluded. Say “the source runs with actual LangChain message classes; traces retain their canonical `message_to_dict` projections, including the declared type and metadata.” This preserves the useful claim without implying that class instances or identity survive serialization.

2. **Surface the capsule method and its exact result in the main article.** The main evaluation table calls these “two recorded bounded slices” with six and 12 schedules, and notes that fresh reproduction replays their models without rerunning source (main article, around line 99). The limitations section adds that the slices ran with mocks and do not increase whole-file admission (around line 112), but the architecture figure presents only the AST-to-IR path. A short evaluation sentence should say that selected hash-pinned original statements/callables were executed against actual pinned LangGraph using explicit offline boundary doubles, then each finite trace model was replayed separately. Include the distinguishing observer result: full-trace classes are 6/6 and 12/12, while content-only projections have four classes and final-answer projections have two in each capsule. This makes the practical evidence legible without presenting the capsules as AST admissions or whole-file execution.

3. **Name the exported exact laws and separate their replay from execution.** The supplement gives finite supports and schedule weights, and correctly says the verifier checks recorded traces rather than proving the run occurred as represented (around lines 200–211). The certificates also export rational observer laws over the complete trace and lossy projections, with every declared schedule represented. State this directly: the six Dili worlds each have weight `1/6`, the 12 Joshua worlds each have weight `1/12`, and the fixed projection laws are aggregated/replayed exactly from the hash-bound trace records. Keep the existing limitation adjacent: this replay certifies consistency of the recorded finite model, not an independently witnessed source execution. The current prose gives enough numbers to infer the laws, but does not quite state this result.

4. **Give the capsule lane the bounded-testing prior art already documented in the capsule report.** The manuscript’s prior-art discussion is careful about established relational cost, automata, and uncertainty methods, but does not position the source-slice capsule against bounded model checking or differential testing (Technical Supplement, §Prior art, around lines 266–288). The capsule report already identifies primary sources for Clarke et al., *Bounded Model Checking Using Satisfiability Solving* (2001), Godefroid et al., *DART* (PLDI 2005), and McKeeman, *Differential Testing for Software* (1998). Add a brief citation/qualification where the capsule method is introduced or in the prior-art section. Describe its contribution as the constrained integration of exact source slices, declared finite schedules, offline doubles, and observer-law replay; do not imply a new bounded-exploration or differential-testing algorithm.

5. **Complete shorthand bibliography records and consider several directly relevant ledger omissions.** The supplement cites Agentproof, CaMeLoT, APPA, FlowSeal, ProMCP, and MAT with authorless or abbreviated records (around lines 350–356). The primary-literature ledger supplies full author/title/status metadata for Agentproof, APPA, FlowSeal, and ProMCP; using those details would make the references independently scannable. The verified ledger also includes Ngo et al.’s *Bounded Expectations* (2018), Radiček et al.’s *Monadic Refinements for Relational Cost Analysis* (2018), Barthe et al.’s *Product Programs and Relational Program Logics* (2016), Köpf and Basin’s adaptive side-channel work (2007), and Gu et al.’s prompt-cache timing audit (ICML 2025), none of which appears in either manuscript bibliography. The article does not make a false claim that these areas are new, and the prior-art search is explicitly non-systematic; however, the first three strengthen the stated foundations, while Gu et al. is especially apt for the observer boundary. A short related-work note and explicit statement that usage equality does not cover cache/timing leakage would close that gap. The present line 288 already distinguishes latency from the selected observer, so this is a citation/grounding improvement rather than a correction to the theorem.

## Scope and proof-boundary assessment

The capsule claims are otherwise well delimited. The supplement calls the cases source-slice executions, identifies the original commits and selected segments, discloses model/retriever/settings/logger doubles, and says that the whole module is not imported. It reports exhaustive *declared* finite supports (6 and 12 schedules; one model call per path and, for Joshua, one retrieval outcome), rather than arbitrary-input or whole-program correctness. The modeled error branch and Joshua’s caught retrieval-error branch are visible, and the text does not claim provider/SDK conformance or deployment probabilities. Keep “modeled error” language: these are finite oracle outcomes, not observed provider failures.

The lossy-observer result is meaningful and appropriately modest. Full traces distinguish worlds that the content-only and final-answer projections merge; the text explicitly avoids attributing a vulnerability to either repository. The full-state definition is also reasonably precise: message/document projections are named, and identity, timestamps, opaque run IDs, OS scheduling, and provider wire behavior are excluded. The message-class wording above is the main remaining ambiguity.

The isolation limitation is candidly reported: macOS Seatbelt probes denied network, writes, fork, and unlisted user files; `/opt` remained readable to launch the pinned Homebrew runtime; the setup is host-specific and not a general sandbox. The main article can stay concise, but its capsule sentence should preserve the “selected immutable slices with mocks” boundary, and the supplement should retain the `/opt` qualification and the verifier-versus-execution distinction.

The Coq claims and exact uncertainty propositions are clearly scoped in the supplement. The normalized-IR theorem lists safety, uniqueness, completeness, routing, and initialization bridges; it explicitly excludes the AST extractor, runtime/provider behavior, and termination. The finite-distance derivation states its finite alphabet, horizon, visible STOP/error convention, rectangular row independence, and supplied row-set premises. No proof-to-compiler overclaim was apparent in the reviewed prose. The main article’s corresponding limitations are adjacent to its claims.
